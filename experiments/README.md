# 实验区 — 自动优化立项（DSPy 式）

状态：**立项，未启动**。这一页把启动条件写死，条件不到不要开跑，
免得拿不可信的指标优化出投机取巧的 prompt。

## 想解决什么

KPE 的规则现在靠人写、人改。DSPy 这类框架的思路是：给定一个可信的
打分函数和一批带标注的样本，让程序自动搜索更好的 prompt 措辞与组合。
它对 KPE 可能有价值的只有窄领域：比如同一类镜头的运镜措辞、风格
token 的组合顺序、负面约束的措辞——范围越窄、指标越硬，越靠谱。

## 为什么现在不能启动

自动优化的地基是「指标可信 + 样本带标注」，现在两样都只齐了一半：

- prompt 层指标有了（`scripts/prompt_lint.py`），但它只量文本卫生，
  拿它当唯一优化目标，程序会学会把 lint 刷满而不是把片子拍好；
- 成片层指标有了量表（`evals/video-rubric.md`），但真实评分样本是 0：
  没有任何一批成片按量表打过分，基线文件都还没有真实数据。

## 启动门槛（全齐才开）

1. 至少 30 条成片按 video-rubric 打过分，且评分者一致（同一人或同一
   VLM 配置），记录存在项目侧的 video scores JSONL 里；
2. 其中至少覆盖 2 个 prompt 版本，能用 `evals/score_video.py` 跑出
   一次有意义的基线对比；
3. 先选定一个窄优化目标（单类镜头、单一维度），不许一上来优化「整体质量」。

## 门槛之前能做的：变体实验

`variant_eval.py` 是脚手架：同一镜头写多个 prompt 变体，它用
prompt_lint 给每个变体打分排序。用途是筛变体、看措辞差异对 lint
维度的敏感度，**结论只对 prompt 层成立**，不能代替成片评分。
真正的 DSPy 接入等门槛齐了再评估，届时指标函数应该是
lint 分与成片分的组合，样本就是上面攒的评分记录。

## 已知风险

- 指标投机：优化器会钻任何指标的空子，量表里没有的维度（比如叙事
  连贯）会被牺牲，所以优化目标必须窄、且保留人工终审；
- 评分者漂移：换人或换 VLM 打分等于换指标，历史样本要重打基线，
  这条和 score_video 的纪律是同一条。
