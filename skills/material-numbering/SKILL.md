# material-numbering — 素材编号

编号不是行政工作，是引用关系的基础设施。分镜 JSON、关键帧、重拍日志、OTIO 时间线全靠同一套编号对上，编号一乱，跨文件引用全断。

## 何时读 references

查命名规则读 `references/data.yaml` 的 `material_naming`，引用语法读 `reference_syntax`，素材清单模板读 `material_list_template`。先看 `references/sections.md` 定位。

## Workflow

1. 项目开始先立编号表：角色 C01 起、场景 S01 起、道具 P01 起，编号一经分配不回收不复用，废弃的素材留号标废弃。
2. 分镜里引用素材只写编号，描述放编号表和角色卡里，不要在每个镜头里重写一份描述——重写必漂移。
3. 生成产物文件名以编号打头（镜号 + 尝试次），让文件系统排序就是生产顺序。
4. 新素材先入表再使用，任何文件里出现表里没有的编号都是错误，校验脚本会抓分镜里的这类问题。

## Gotchas

镜号不要用 S 开头。旧分镜表用过 S01 当镜号，和场景编号正面撞车，现行约定镜号用 SHOT-01 形式，`schemas/storyboard.schema.json` 和校验脚本都按这个执行，看到旧表先改号再用。

编号不要带语义。C01 不要写成 C-男主-01，语义进名字迟早和内容对不上，语义放清单的备注列。

版本别进编号。同一素材改版用 _v2 后缀或尝试次，不要新开一个编号，不然引用方不知道该指谁。

## 规则

- 编号体系以本技能为准，分镜 schema、重拍日志、OTIO metadata 里的编号都从这里出。
- 引用必须可解析：写了编号就要能在编号表或分镜的 characters/assets 里找到本体。
- 跨集项目编号不重置，集号放文件名前缀或清单分组里，不进编号本身。
