# anti-slop — 弱词替换

形容词不产生画面。模型读到空话词只会往平均值靠，读到具体的光源、景别、运镜才知道要生成什么。这个技能管替换，机器检查在 `scripts/prompt_lint.py`，那边是门禁，这边是词表和替换思路。

## 何时读 references

替换某个弱词时读 `references/data.yaml` 的 `weak_words_replacement` 一节，按词查。先看 `references/sections.md` 定位行号，只读命中的段。`strong_words` 一节是正面词库，写的时候主动取用。

## Workflow

1. 通读 prompt，把抽象形容词和感受词全标出来：风格类、质感类、情绪类、程度类。
2. 逐个替换：每个弱词换成具体描述——光源是什么、在哪，镜头多远、怎么动，画面里什么东西在动。
3. 替换完跑 `scripts/prompt_lint.py`，分数和命中项以脚本为准，不要靠肉眼觉得干净了。
4. 剩下的弱词如果确实删不掉，问自己它约束了模型的哪个选择，答不上来就删。

## Gotchas

替换不是换同义词。把「电影感」换成「电影级质感」等于没换，lint 照样扣分。要换成可验证的东西：侧光、浅景深、缓慢推进，每一项都能在画面里指出来。

负面词里也藏弱词。「不要模糊、不要廉价感」这类否定式空话一样无效，改成正向的具体描述。

中文 prompt 更容易堆四字感受词，具体词目在 data.yaml 的弱词表里（感受类后缀那批）。处理方法一样，全部落到光、物、动作上。

## 规则

- 一句 prompt 里至多保留一个不可替换的风格指称（如导演名），其余全部具体化。
- 替换后 prompt 变长是正常的，但只许长在信息上，不许长在修饰上。
- lint 不过门禁不要交付，先改词再改结构，顺序反了会越改越虚。
