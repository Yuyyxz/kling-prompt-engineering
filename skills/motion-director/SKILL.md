# motion-director — 运动导演

运动写不好有两种死法：写太少，画面僵成 PPT；写太多，模型把三个动作揉成一团。中间地带是：一镜一个主要运动，节奏有起落。

## 何时读 references

首尾帧模式读 `references/data.yaml` 的 `first_last_frame_mode`；运动分层读 `temporal_motion` 与 `motion_rhythm`；指令格式读 `motion_instruction_format`。先看 `references/sections.md` 定位。

## Workflow

1. 先分清这镜的运动归谁：主体动、镜头动、还是环境动（风、雨、人流）。主要运动只选一个，另外两个最多做背景层。
2. 写运动节拍：起始状态、一个可见节拍、结束状态。和时间轴三层对齐——状态层给首尾，运动层给节拍，节奏层给快慢。
3. 运镜写全三要素：方向、速度、幅度。「缓慢推进」要能回答从哪推到哪、几秒推完。
4. 首尾帧模式下，运动 prompt 只写两帧之间的变化，不重复描述画面内容，画面归关键帧管（见 keyframe-generator）。
5. 检查运动与时长的匹配：动作量超过这几秒能演完的量，拆镜，不要加速硬塞。

## Gotchas

图生视频里把静止画面的内容再写一遍进运动 prompt，模型会试着重新生成画面，漂移就这么来的。I2V 只写运动，这是 Runway 官方指南和这边实测一致的结论。

形容词管不了速度。「快速地跑」和「缓慢地跑」模型分不清多少，给秒数和距离参照：三秒内跑出画面，比什么副词都准。

多主体同镜各自动，十有八九糊成一团。要动就给主次，主要主体动，次要的只许微动或不动。

## 规则

- 一镜一个主要运动，写不下就拆镜，不许用「然后、接着」串联多个节拍。
- 运镜术语用标准词表（推拉摇移跟升降），不要自创说法。
- 运动约束（什么不许动）写进 constraints，和分镜 JSON 的字段对齐。
