# failure-atlas — 失败诊断图谱

不要让用户盲目重试。先定位是哪类问题，再改对应那一句，最后只改一处验证。

## 何时读 references

先读 `references/quick-diagnosis.md`，那是速查表，一行一个问题，先在里面把类别定下来。定下类别后读 `references/diagnosis-examples.md` 看具体改法，要查完整的原因解法全表读 `references/data.yaml`。问题复杂或速查表盖不住时，去根目录 `18-troubleshooting-gallery.md` 查深案例，那里有验证方法。

## 诊断流程

1. 先看症状归类，8 类先定一类：镜头、光影、运动、参考角色、时长、构图、音频、安全。
2. 再看具体问题。比如镜头类里是模糊、抖动还是角度不当，角色类里是变形、不一致还是识别度低。
3. 说清根因再动手改。根因要落到 prompt 的某一句或某个缺失字段上，落不下来就先补观察，不要猜着改。
4. 一次只改一个变量。改之前告诉用户改什么、预期会变什么，改完按 18 里的验证方法验。
5. 把这次诊断记进重拍日志，模板在 workflows/retake-log-template.md。记下模型版本、改的变量、结果判定，攒下来的记录是这个图谱以后更新的来源。

## Gotchas

面部变形十次里有八次是近景加大运动撞在一起。修法是二选一，拉远或者减速，不要在原 prompt 上继续加保持面部的词，加多少都盖不住结构冲突。

续写后变脸不要在续写 prompt 里补救，要回到原始参考图重新锚定。拿已经漂了的输出继续续，越续越远。

动作卡住和速度忽快忽慢，先查节拍数。5 秒塞了三个动作就是时长类问题，改 prompt 措辞没用，拆镜头才有用。

声音对不上多半是声音写得太总。只写环境音三个字等于没写，改成命名具体声源。

同一个问题改两次还没好，停。回到导演五问和预算分配重看结构，不要在原 prompt 上越堆越长，堆到最后没人知道哪句在起作用。

## 规则

- 先诊断再重试，没有诊断结论不许直接给新 prompt。
- 安全和版权问题不绕过，改描述或换素材。
- 修复建议一次只给一个主要改动，可以附带说明为什么不改其他的。
- 诊断结果要能被验证，说清看第几帧、看什么位置来判断修没修好。
