# 诊断示例 — 从症状到改好的 prompt

什么时候读这个文件：已经在 `quick-diagnosis.md` 里定下类别、要看具体怎么改时。8 类问题的完整原因和解法全表在同目录 `data.yaml`，根目录 `18-troubleshooting-gallery.md` 有 5 类 23 条深案例，两边配合用。

## 画面模糊

病根多半是 prompt 里没有指定焦点。改法是把焦点写死，焦点在主体面部，配浅景深、背景虚化，运镜用缓慢推进。改完验前三帧，主体清晰、背景虚化稳定才算过。

## 角色面部变形

病根是参考图质量差或近景加大运动。改法是换清晰正面参考图，prompt 里写保持面部特征不变，镜头拉到中景，运动压到缓慢移动。面部和运动幅度只能保一个，这个取舍要在改之前跟用户说清，不要改完才发现表情没了。

## 动作不自然

病根是动词太虚，只写了移动、活动这类词。改法是换成具体动词加方向和终点，缓慢转身要写清转向哪边、停在什么姿态。 prompt 里同时出现方向矛盾的词时先删矛盾，不要叠加新词去盖。

## 声音不匹配

病根是只写了环境音、配乐这类总称。改法是命名具体声源，铁门电机嗡鸣、雨打钢架、脚步碾过石板，声音跟着画面里正在发生的事走。声音中途消失的，加声音从头到尾持续这类约束。

## 生成被拒

先分清是敏感词触发还是版权问题。敏感词换同义的安全表达，版权内容换原创描述。不要教用户绕审核，改描述或换素材，同一条被拒两次就换方案，不要换着词反复试探平台。

## 快速判断表

画面太亮先查过曝，降光线强度、加阴影方向。画面太暗先查欠曝，补光源。视频太短先查节拍数和时长配比，5 秒塞了三个动作就是时长类问题，不是模型问题。构图奇怪先查主体位置有没有锚定，写清主体在画面哪一侧、占多大。
