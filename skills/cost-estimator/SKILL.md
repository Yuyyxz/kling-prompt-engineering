# cost-estimator — 成本估算

估算的价值不在精确，在提前知道钱会烧在哪：多数项目超支不是单价贵，是重拍次数没算进去。

## 何时读 references

查某个模型的计费模型和单价读 `references/data.yaml` 的 `cost_models` 与 `cost_formula`，先看 `references/sections.md` 定位。预算管理和优化手段在 `budget_management`、`cost_optimization` 两节。

## Workflow

1. 先定生成清单：多少个镜头、每镜时长、目标模型和分辨率档位。清单来自结构化分镜，不要凭感觉数。
2. 按 cost_formula 算首轮成本，再乘重拍系数：简单镜头 1.3、有人脸近景或文字 2.0、复杂运动 2.5 起，系数依据是重拍日志的历史数据，有自己的日志就用自己的。
3. 给出区间而不是单点数，并注明用的哪家渠道价、哪天查的。
4. 交付时把估算和实际对账的入口留好：实际成本记进重拍日志的 cost 字段，项目结束回看估算偏差。

## Gotchas

data.yaml 里的单价是快照，平台调价很勤。给用户报预算前必须去所用渠道复核当前价，复核不了就在估算里写明价格日期，不要把旧价当现价。

不同渠道计费单位不一样：有的按秒、有的按次、有的按 token（Seedance 2.5 在 fal 是按 token）。跨模型比价先统一到「每成品秒」再比，不然比的是口径不是价格。

延长、续写、参考视频输入都可能单独计费（Kling 4.0 的参考视频按源视频秒数加收一类），只算主生成会低估。

## 规则

- 模型硬规格（时长上限等）以 `adapters/model_facts.yaml` 为准，这里只管钱，不管规格。
- 估算里必须分开写首轮成本和含重拍的总预算，两者混写等于没估。
- 预算不够时先砍镜头数和重拍系数高的镜头，不要全线降分辨率，画质降了重拍反而更多。
