# visual-pipeline — 可视化 Pipeline

这个技能是管线的概念层：把生产拆成节点（输入、剧本、分镜、关键帧、生成、重拍、合成、交付），讲清节点之间能怎么连、什么不能连。可执行的管线在配套仓库 ai-video-production-workflow（P0–P7 阶段门）和本仓的 scripts 里，这边不重复实现，只负责设计时的概念对齐。注意：配套仓库的现状本技能未逐项复核，引用它的阶段细节前先看那边的文档。

## 何时读 references

节点类型读 `references/data.yaml` 的 `node_types`，连接规则读 `connection_rules`，示例读 `workflow_examples`。先看 `references/sections.md` 定位。这个技能的数据量最小（174 行），需要时整份读也行。

## Workflow

1. 先画节点：把这次生产实际经过的阶段列出来，不经过的不要画，管线图不是许愿池。
2. 按 connection_rules 连边：每个节点的输入必须能由上游节点的输出满足，对不上的地方就是要补人工或补脚本的地方，先标出来。
3. 每个节点标质量门：过门的标准是什么、谁判、不过回哪个节点。没有质量门的节点等于直通，问题会攒到最后一起爆。
4. 回环只许出现在重拍节点：生成 → 判定 → 重拍是有界回环（尝试预算封顶），其他回环多半是设计没想清。

## Gotchas

节点拆太细，交接成本吃掉全部收益；拆太粗，质量门无从下手。按「一个节点一个可判定产物」拆：分镜 JSON、关键帧图、成片文件，各自能独立验收。

图画得漂亮不代表能跑。每个节点最后都要落到一个脚本、一个技能或一个明确的人工动作，落不下来的节点删掉或标成待建。

## 规则

- 管线设计先于工具选型：先定节点和质量门，再选每个节点用什么实现。
- 改管线先改这里的概念图和连接规则，再动实现，不然图和实现迟早分家。
