# domain-skills — 领域垂直模板

通用 prompt 代替不了领域知识。电商要干净，恐怖要压迫，美食要触感。先选对领域，再按那个领域的语法写。

## 何时读 references

定下领域后读 `references/domains.md` 查该领域的钩子、时间轴骨架和注意事项。要查某个领域的完整参数、运镜光线声音细表或示例 prompt，读 `references/data.yaml`，按领域名搜索。不要一上来就读 data.yaml 全文，只读命中的那一段。

## Workflow

1. 先定领域。用户没说清内容类型时问一句，是卖货、叙事、口播还是展示，定不下来不要动笔。
2. 读 domains.md 对应小节，拿到这个领域的钩子类型和时间轴骨架。
3. 按导演五问过一遍，领域语法只管形式，戏剧功能还是五问说了算。
4. 按领域结构填槽位：钩子、时间轴分段、运镜、光线氛围、声音设计、参考策略、平台优化，缺一项补一项。
5. 输出前按根 SKILL.md 的 Quality Gate 自检，光源、运镜、声音、约束四项齐了才交。

## Gotchas

领域选错比 prompt 写差更伤。把电商的干净明亮套到恐怖题材上，每句都合格，合起来全错。

产品类领域不要让模型渲染文字和 logo。电商、产品 360、动态设计广告都一样，文字放后期，prompt 里写无文字约束，产品身份靠参考图锁。

打斗和动漫容易把动作堆满。一个镜头一个节拍在领域里同样算数，动作密度超了先拆镜头，不要靠加快速度硬塞。

竖屏和横屏不要共用一条 prompt。社交钩子、电商默认竖屏，电影风格、音乐视频默认横屏，构图和前 2 秒的打法完全不同。

美食最容易写回感受词。食欲、美味、诱人都要换成蒸汽、拉丝、滴落、油光这类能拍到的东西。

## 规则

- 风格叠加不超过两个，一个导演风格加一个视觉或情绪风格就够了。
- 每个领域模板的五件套不能缺：钩子、时间轴、运镜、光线、声音。
- 平台优化只改构图、节奏和留白，不要为平台改掉领域的核心语法。
- 领域之间借结构可以，借视觉语法要说明，用户确认了再混。
