# retake-protocol — 重拍协议

重拍是生产里最贵也最容易乱来的环节。协议管三件事：判定标准、单变量纪律、什么时候停手。记录格式在 `workflows/retake-log-template.md`，聚合分析用 `scripts/retake_report.py`，失败归类用 failure-atlas 的 8 类，本技能是执行纪律本身。

## 何时读 references

判定标准读 `references/data.yaml` 的 `evaluation_criteria`，预算读 `attempt_budget`，流程与清单读 `retake_workflow`、`evaluation_checklist`。先看 `references/sections.md` 定位。

## Workflow

1. 先判定：对照评判标准和分镜的戏剧功能，这镜是收、重拍、还是废弃。判定当场写进重拍日志，不要攒到最后补。
2. 定失败归类（8 类）和具体症状：第几秒、什么位置、出了什么问题。写不出症状就不许开重拍，先看清再动手。
3. 只选一个变量改：运镜、动作、光线、参考、时长……选最可能的那一个，其余逐字不动，prompt 哈希跟着日志记。
4. 重拍后回到第 1 步重新判定。新结果比旧的好不等于达标，按标准判，不按进步判。
5. 触到尝试预算上限还没过，停。回导演五问和预算分配重审这一镜的定位，或者诚实退出换实现方式，不要在同一变量上磨第五次。

## Gotchas

连续两次重拍不过，问题多半不在你改的那个变量，在分镜设计本身。回上游改分镜，不要在生成层死磕。

「顺手把另一个小问题也改了」是单变量纪律最常见的破口。两个变量一起改，好了不知道谁的功劳，坏了不知道谁的锅，这次重拍等于白烧。

判定标准会漂：看多了会不自觉放宽。拿第一镜的判定尺度量最后一镜，过不了就是过不了。

## 规则

- 没有日志记录的重拍不算数：模型版本、prompt 哈希、改动变量、判定、成本，缺一项这条不许关。
- 同类失败攒够 3 次，按 retake_report 的候选机制提炼进 failure-atlas 候选，人工过后才进正文。
